# ADR-0005：每個版本只含發布時勾選的券商，各家各自計算最新版本與最低支援版本

Date: 2026-10-13
Status: Accepted

## Context

使用者要求 QtOrder 推到 `main` 後只針對有異動的券商打包，並由使用者決定每次發布哪幾家（QtOrder ADR-0043、ADR-0044）。ADR-0004 規定每個版本必須有三家共六個下載檔案、三家不能獨立升版，擋住了這個流程。

QtOrder 的啟動器本來就按券商讀更新清單：只讀 `brokers[自身券商]`，`stable` 必填、`preview` 缺少時用 `stable`、`min_version` 選填；找不到自身券商時不更新、照常啟動本機版本。三家的最新版本不同，啟動器也讀得懂。發布中心還沒有任何正式版本，發布紀錄仍是模擬資料。

## Decision

- 版本號仍三家共用、不重複使用；每個版本包含一到三家，由下載檔案推導，不另存欄位。包含的每一家剛好一個安裝程式與一個更新套件。
- 發布紀錄改為 schemaVersion 3：`minimumVersions` 以券商為鍵，取代單一的 `minimumVersion`。每家的最低支援版本必須是包含這家的未撤回穩定版；還沒有任何版本的券商不能設定。
- 各家各自計算最新穩定版、最新預覽版、`min_installer_version`（只看包含這家的版本）與最低支援版本。
- 版本號不分券商都隨發布時間遞增，因為 QtOrder 只從 `main` 發布；成為穩定版的順序則按券商檢查，所以一家晉升了較新的版本後，另一家仍能晉升較舊的版本。
- 更新清單格式不變（schemaVersion 2）；還沒有穩定版的券商不列入。
- 每家的第一個穩定版同時設為該家的最低支援版本；首發仍會清掉模擬資料。

## Considered Options

- **維持每版三家六個檔案（ADR-0004）**：使用者要求能只發布有需要的券商。
- **各券商獨立版本號與 tag**：QtOrder 的版本號要拆成三個來源，發布紀錄、版本說明與 tag 都要按券商分；共用遞增的版本號就足以讓各家各自前進。
- **版本號遞增只按券商檢查**：只從 `main` 發布時，較晚發布的版本號一定較大；不分券商檢查能擋下 `CurrentVersion` 被改小的錯誤。
- **最低支援版本維持一個**：三家前進的速度不同，單一的最低支援版本必須是三家都有的版本，會讓某家無法強制客戶離開有問題的版本。

## Consequences

ADR-0004 中「每版必須包含三家共六個資產」與「三家不能獨立升版」由本則取代，其餘（`broker` 欄位、檔名規則、不接受 `mega`、更新清單 schemaVersion 2）不變。發布中心頁面要能按券商顯示各自的最新版本。
