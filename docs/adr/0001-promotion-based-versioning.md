# 版本採晉升制，版本號只用純數字

QtOrder 的啟動器用 .NET 的 `System.Version` 比較版本，而且啟動器不會自我更新，`1.6.0-preview.1` 這類 SemVer 預覽標記會讓它解析失敗。因此預覽版與穩定版不靠版本號區分：每個新版本先發布到預覽版，驗證通過後把同一個版本、同一份下載檔案晉升為穩定版；緊急修正可以不經預覽版直接發布為穩定版。代價是穩定版的版本號會跳號（例如 1.5.1 之後直接是 1.6.1）。

## Considered Options

- **SemVer 預覽標記並改寫啟動器**：裝在客戶電腦上的啟動器只能靠重新安裝才會更新，日後只要有一台舊啟動器還在用，預覽版本號就會讓它出錯；而且穩定版需要重新建置，客戶拿到的不是驗證過的那份檔案。
- **以第四段數字當預覽序號（1.6.0.1）**：`1.6.0.1` 大於 `1.6.0`，預覽版反而排在它要成為的穩定版之後，和「先行版本」的意思相反。

## Consequences

- 發布紀錄要能表達「這個版本何時晉升」，頁面與更新清單都以未撤回的最高版本號作為各通道的最新版本。
- 預覽版沒有比穩定版新的版本時，更新清單的預覽版改指向穩定版，避免選預覽版的客戶被降級。
